# ページ権限

- `data/pages.json` の `roles` がページ閲覧とメニュー表示の基準です。役割は `worker`、`family`、`admin` です。
- `common/ui.js` の `verifyLocalAuth()` はログイン確認後に `page-access.js` で現在のURLの権限を確認します。戻り値が `false` の場合はページの表示・初期化を行わないでください。
- 権限不足ではログイン情報を削除せずトップへ戻ります。設定の読み込みに失敗した場合もアクセスは許可しません。
- パスはサイトのルートから解決します。管理ツールは `/admin/` から始まる絶対パスで登録してください。末尾 `/` は `index.html` として照合します。
- クエリ条件が指定された登録項目を優先します。機械IDやフィルタなど、登録項目にないクエリは権限に影響しません。
- `accessOnly: true` は権限判定だけに使う補助ページです。トップメニューとQR生成の候補には表示しません。
- 未登録の `/admin/` 配下は管理者限定、その他の未登録ページは拒否します。新しいページを追加した際は台帳登録と、表示前の共通認証を必ず追加してください。
- 管理トップは管理者限定です。家族も閲覧できる管理サマリーは `/admin/summary-view/index.html` に登録し、トップにも入口を表示します。
- 機械の `allowedPageIds` はQRの表示設定です。機械QRはユーザーの `roles` と機械設定の両方に一致する作業ページだけを表示します。

既存台帳の `nursery-log`、`variety-analysis`、`year-compare` の参照先はローカルには存在しません。公開環境での利用状況が未確認のため、登録は保持しています。削除・URL変更は公開環境を確認してから行ってください。

## セキュリティ上の限界

これはブラウザーでの表示制御であり、サーバー側のアクセス制御ではありません。静的HTML・JSON・CSVの取得や、保存APIへの直接リクエストは防げません。役割やセッション情報もブラウザー内にあり、サーバーで検証できる認証資格情報ではありません。

保存APIの `presign` と `append` の実装はこのリポジトリにはありません。サーバー側では検証可能な認証情報に基づきユーザー・役割・書き込み先を判定し、マスタ変更や削除を管理者限定にする必要があります。読み取り側の保護にはCloudFront/S3の配信設定も必要です。

今回の確認は、ブラウザーで実モジュールと権限台帳を用いた役割別テスト、および模擬ユーザー・模擬保存領域による共通認証の接続テストです。本番の保存APIや実ユーザー情報は変更していません。
